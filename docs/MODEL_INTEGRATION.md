# 正式模型接入建议（待实现）

本文件为建议协议与实施顺序，**不是已存在的 API 文档**。当前页面全部在浏览器内执行，没有以下路由或后端服务。

## 建议接入顺序

1. 预测与参数：替换合成输入，核对时间、单位、来源和版本。
2. 调度：后端返回逐时计划、求解状态及诊断；前端独立复算与展示。
3. 电网：增加独立潮流检查结果，明确数据不足和越限状态。
4. 故障：诊断建议与恢复反馈分离；有效设备状态更新后再重规划。
5. Agent：调用已验证的专业工具，解释已存在的证据和结果。

Python 模型应由后端运行，前端用 HTTP 获取结果；API 密钥不写入前端。跨域、认证、超时与部署由集成时统一处理。

## 建议接口表

| 建议路由 | 专业交付 | 页面用途 |
| --- | --- | --- |
| `POST /api/forecast` | 负荷与光伏序列、发布时间、有效窗口、版本 | 预测曲线与调度输入 |
| `POST /api/carbon-series` | 分时碳因子、计算方法、来源 | 购电碳排目标与核算 |
| `GET /api/assets` | 光储功率/容量/效率/SOC等参数与版本 | 配置与约束 |
| `POST /api/dispatch` | 逐时计划、费用/碳排、求解状态、诊断 | 三目标计算与比较 |
| `POST /api/grid/check` | 潮流/约束检查、越限信息、检查范围 | 与独立数值复算分别展示 |
| `POST /api/fault/diagnose` | 诊断、影响资产、证据与恢复建议 | 事件分析；不直接更新状态 |
| `POST /api/recovery/feedback` | 有效反馈、资产可用性、状态版本 | 更新状态后触发调度 |

路由、同步/异步方式及字段最终由团队确认。对于耗时求解，可改为任务ID与状态查询。

## 公共元数据

各模块约定以下字段，时间必须包含时区或UTC偏移：

```json
{
  "park_id": "campus-demo",
  "timezone": "Asia/Shanghai",
  "start_time": "2026-02-19T00:00:00+08:00",
  "interval_minutes": 60,
  "point_count": 24,
  "data_type": "synthetic",
  "data_version": "DEMO-D1",
  "model_version": "module-version",
  "status": "ok",
  "missing_fields": []
}
```

- `data_type` 区分实测、预测、合成和假设，不将缺失值补零伪装成有效数据。
- `status` 至少区分成功、数据不足、不可行、失败；不能把所有结果写成“通过”。
- 预测额外提供 `issued_at`、有效窗口；实测参考数据及其版本单独说明。
- 返回原始数值，展示层负责四舍五入；数组长度、时区和单位不匹配时阻断受影响流程。
- 园区、计划、事件和设备状态版本应可关联；迟到、重复或过期反馈不得覆盖有效状态。

## 与当前页面的适配

当前 `Engine.dataset()` 输出 `hours/load/pv/actual/actualPV/price/carbon` 数组，功率单位为kW，价格为元/kWh，碳因子为kgCO₂/kWh。固定1小时粒度，逐时功率数值才可直接作为该小时电量使用；接入15分钟数据必须相应修改时间积分及验证，不能只换数组长度。

当前计划逐行包含：

| 当前字段 | 含义 / 单位 |
| --- | --- |
| `h` | 时段序号0—23 |
| `load`, `pv`, `grid` | 负荷、光伏、购电功率，kW |
| `charge`, `discharge` | 充电、放电功率，kW |
| `curtail` | 弃光功率，kW |
| `energy` | 时段末储能能量，kWh |
| `soc` | 时段末SOC，百分数0—100 |
| `price`, `carbon` | 时段电价、碳因子 |

`runPlan` 当前同步调用 `Engine.plans`。接入真实API时需要改成异步流程：输入确认 → 请求中 → 成功/失败 → 独立复算 → 展示。保存不可变的输入快照与请求ID，丢弃过期响应，不让旧请求覆盖新配置。

独立复算和电网校核不能相互替代。当前 `Engine.verify` 不支持任意真实模型约束，接入前应按各成员模型假设调整复算规则。

## 故障状态约定

当前演示状态：`full` 完全恢复，`partial` 部分恢复（假设功率35%），`failed` 恢复失败，`none` 无反馈。35%是演示值，正式接口应提供具体资产及有效功率/可用性。

恢复建议不等于设备已恢复。前端只有收到有效反馈后才能更新设备状态。重规划应保留事件前实际已执行的历史动作，并关联原计划。当前实现为14:00故障的全日对照仿真，不能直接等同真实在线调度。

## 每个模块的最小联调验收

- 正常输入返回可核对的样例，单位、窗口、版本一致。
- 缺数据、超时、求解不可行等状态独立显示，不使用旧结果冒充。
- 正式结果明确区别于模拟数据；模型效果与接口接通分别记录。
- 图表、解释、方案比较和报告引用同一个计划版本。

## 前置输出状态

当前 `outputForecast()` 和 `saveAssets()` 分别记录预测、碳因子与设备参数的有效输出快照。`dispatchReady()` 同时检查两类快照，导航、计划计算和故障重规划共享此检查。接入真实API后，只能在成功取得完整且属于当前请求的专业输出后设置就绪状态；不能在请求发出时设置。日期或相关输入变化后，调用 `invalidateOutputs()` 或 `invalidateOutputs("parameters")` 使对应结果失效。界面不额外显示这条前置规则。
